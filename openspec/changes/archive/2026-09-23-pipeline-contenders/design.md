## Decisions

- **A pipeline is a contender, not a new matrix axis.** It goes through `expand`, bout IDs, `score` and `report` unchanged. Comparing "finder" with "finder + verifier" is just two rows in the same table.
- **Stages reference contenders by id, in the same file.** No inline stage definitions, so a stage is configured once and can also be a contender on its own. `baseline` is always a valid stage (a verifier pass with no skill). Nesting is refused, and since a pipeline can only point at leaf contenders, cycles can't happen; a pipeline naming itself fails the same way.
- **Stage lock facts are copied into the pipeline's lock entry** (`stage_locks`, deep copies so the YAML has no anchors). A pipeline bout then runs from its own entry, and stage-only contenders never enter `lock.contenders`, so they don't get bouts. The pipeline's `tree_hash` and `config_hash` fold in the stages', so the existing drift check reports an edited stage as `contenders.<pipeline>.tree_hash changed` without a new code path. `verify_prompt_sha256` is added to the drift fields.
- **`run_hash` = hash(kind, stage run hashes in order, verify prompt hash).** Editing a stage or `verify.md` changes only the pipeline's bout IDs; plain contenders keep theirs.
- **One `run_stage` for everything.** A plain bout is a single stage written straight into the bout dir. A pipeline bout calls it once per stage with `stages/<n>-<id>/` as the output dir and a fresh ctx/cfg dir and container name. The arena is prepared once per bout and mounted read-only into every stage.
- **Runner seam.** `run_bout(..., runner=podman_bout_runner)` takes a `Launch -> ContainerRun` callable, like the judge's `Runner`. The podman runner does create, monitor, stream with live limit kills, OOM check and cleanup. Fake runners skip the egress proxy (same rule as the judge). The status is decided from the transcript (limits re-checked from the lines), so fakes and podman agree.
- **Limits and budget apply per stage.** Each stage is a normal bout run with the full `runtime.limits` and `--max-budget-usd`. Round ceilings (`run --max-cost-usd/--max-tokens`) see the summed usage. Splitting one budget across stages would make a pipeline's finder weaker than the same finder alone, which defeats the comparison.
- **Verifier input is data, blinded.** Only the schema's finding fields go in (no summary or coverage); free-text fields go through the judge's blinder (contender, skill, plugin and bout ids redacted). The JSON sits in a backtick fence longer than any backtick run inside it, so finding text can't close it. Blinding moved to `skillordeal/blind.py` so `bout.py` doesn't import the judge; `blind_terms` also walks `stage_locks`.
- **Same output schema.** Verifier stages answer with `findings.schema.json`, so the final output is scored exactly like a plain bout. They may correct file/lines/severity/confidence but are told not to add findings.
- **Stop at the first failure.** The bout takes that stage's status and reason and records `failed_stage`. If stage 1 is `ok` with zero findings, later stages are `skipped`: there's nothing to verify and running them would only cost money.
- **Summed record fields.** usage (cost, tokens, durations, turns, per-model), tool calls and egress counts are summed; resource peaks are maxed and CPU/IO summed. `first_turn_prompt_tokens` and `init` are stage 1's because that's the stage comparable to a plain bout (the forced-injection check). `skill_fired` is true only when every skilled stage fired.
- **Top-level artifacts.** `findings.json` is the last stage's, `prompt.md`/`transcript.jsonl.zst`/`stderr.log`/`resources.jsonl` are stage 1's copies, so `show`, `transcript` and the review UI work unchanged.

## Risks

- A verifier that also finds new issues goes against the prompt; nothing enforces "no new findings". Scoring counts whatever the last stage returns, so a verifier that re-reviews would show up as a recall change, not a silent error.
- The verify prompt is engine-owned. Changing it changes every pipeline's bout IDs, which is intended but means old pipeline bouts re-run.
